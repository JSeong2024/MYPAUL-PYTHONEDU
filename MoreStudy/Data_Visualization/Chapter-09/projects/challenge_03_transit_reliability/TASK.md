# Challenge 03 — City Transit Reliability Audit

## 문제 상황
다중 원천 운영 자료 검증·수집률·사고·재현 가능한 통합 보고서가 필요합니다. 관측이 없는 시간과 값이 0인 시간을 혼동하지 않고, 선택 대상이 달라져도 보고서를 생성해야 합니다.

## 요구사항
1. `data/`의 원본 파일을 수정하지 않습니다.
2. 잘못된 값, 중복 관측, 등록되지 않은 참조 ID를 검증합니다.
3. 그래프에는 제목·축 단위·집계 기간·데이터 출처를 표시합니다.
4. 기록이 없는 슬롯은 관측 0건으로 표시하되, 측정값 0으로 대체하지 않습니다.
5. 그래프 PNG와 집계 CSV, 실행 요약 JSON을 `output/`에 생성합니다.
6. 빈 필터 결과와 잘못된 입력에서 이해할 수 있는 오류를 제공합니다.
7. 결과 파일은 반복 실행해도 예측 가능한 형태여야 합니다.

## 시작 방법
`starter.py`를 완성한 뒤 `python projects/challenge_03_transit_reliability/starter.py`로 실행합니다.

## 완료 기준
생성된 CSV의 집계값이 원본의 유효 데이터 기준과 일치하고, PNG의 축·범례·단위가 명확해야 합니다. 파일이 만들어졌다는 사실만으로 합격 처리하지 않습니다.

## Challenge 03 추가 조건 — 필수
1. **다중 원천 결합:** 운행 관측·정류장 기준정보·사고 이력 간 키 일관성을 검사합니다.
2. **데이터 감사:** 동일 정류장·시각 중복은 두 행 모두 제외하고 감사 파일에 이유를 기록합니다.
3. **예정 슬롯 복원:** 12개 정류장, 30일, 06–22시의 모든 예정 슬롯을 구성합니다.
4. **재현성:** 고정 입력 데이터에 대해 동일한 요약 결과와 해시를 출력합니다.
5. **불완전 날짜:** 17시간 관측이 완비되지 않은 날은 총승차 인원 비교에서 별도 표시합니다.
6. **원인 추론 주의:** 사고 날짜와 지연 시간이 겹친다고 사고가 지연의 원인이라고 단정하지 않습니다.
7. **규모:** 수천 행 이상을 처리하고, 선택 정류장 수가 변경되어도 레이아웃이 깨지지 않습니다.
8. **보고서:** 라인별 비교·정류장별 히트맵·관측 커버리지·감사 결과·사고 건수를 포함합니다.
9. **오류 주입 테스트:** 중복 참조 ID, 음수 승차 인원, 비정상 시각, 사고의 미등록 정류장 등을 검사합니다.
10. **품질 게이트:** 예상 집계 불일치 또는 참조 데이터 오류 시 조용히 성공 처리하지 않고 실패해야 합니다.

**난이도는 복잡한 계산 공식이 아니라, 상충되는 요구사항을 일관되게 만족시키는 데서 발생합니다.**
