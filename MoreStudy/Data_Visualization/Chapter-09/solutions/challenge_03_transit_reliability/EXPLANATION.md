# Challenge 03 — City Transit Reliability Audit — Reference Solution Guide

이 코드는 **유일한 정답이 아닌 모범 구현**입니다. 데이터 검증은 `core/analytics.py`의 독립 함수로 수행하므로, 시각화 코드가 바뀌어도 데이터 품질 기준을 재사용할 수 있습니다.

- `reference_solution.py`를 실행하면 `output/challenge_03_transit_reliability/`에 요약 CSV, 그림 PNG, JSON을 저장합니다.
- 원본 데이터는 변경하지 않습니다.
- `build_report()`는 결과 수치가 들어 있는 사전을 반환하여 테스트에서 재사용할 수 있습니다.
- 집계값을 계산한 데이터 범위와 그래프에 그린 데이터 범위를 일치시킵니다.

## 검토 항목
1. 관측 레코드의 유일성, 참조 ID, 유효 범위를 확인합니다.
2. 그래프 축 제목에 단위가 있는지 확인합니다.
3. 누락된 기록을 실제 측정값 0과 구분합니다.
4. 출력 폴더를 지운 뒤 재실행해 같은 요약이 만들어지는지 확인합니다.
5. 조건이 달라질 때 그래프 범례 및 레이아웃의 가독성을 다시 확인합니다.

## 확장 과제
입력 데이터의 기간과 대상 개수를 바꿔서 동일한 검증 규칙이 유지되는지 확인하세요. 그림의 미관에 대한 평가는 테스트 코드만으로 완결되지 않으므로 사람이 직접 검토해야 합니다.

## Challenge 03 확장 설계

`reliability_engine.py`는 **데이터 계약과 품질 게이트**, `cli.py`는 **선택 정류장에 따른 집계와 매니페스트 생성**을 담당합니다. 첫 번째 파일이 데이터를 검증하고 두 번째 파일은 검증된 데이터만 사용하여 보고서를 생성하므로, 기능을 교체하거나 테스트하기 쉽습니다.

- 정류장 및 사고 참조 ID의 유일성 검증
- `accepted + excluded == raw` 검증
- `accepted == observed expected slots` 검증
- 매일 17개 슬롯의 관측 완전성 계산
- 완전한 관측일만을 이용한 비교 집계
- 입력 및 출력 파일의 SHA-256 기록
- 동일 입력·같은 설정의 두 실행이 동일한 `manifest.json`을 갖는지 검증

**주의:** 이 모범 구현은 교육용이며, 실제 교통 운영 정책이나 규정에 따른 완전한 서비스 품질 평가 시스템을 의미하지 않습니다. 사용자는 데이터 수집 편향, 운영 중단과 유효 승객 0, 사고 발생 보고 시각의 정확성 등을 별도로 확인해야 합니다.
