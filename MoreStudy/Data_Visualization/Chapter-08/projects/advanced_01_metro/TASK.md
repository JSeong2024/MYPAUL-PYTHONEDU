# Advanced Project — Urban Metro Operations Dashboard

## 문제 상황

도시철도 운영 기록을 담당하는 팀에서는 7개 역의 시간대별 승차 인원과 평균 지연시간을 확인하고 있습니다. 원본 기록에는 중복·오류·누락이 있어, 그래프만 그리면 실제 관측 현황을 잘못 설명할 수 있습니다.

운영 담당자가 역사와 기간을 선택하면 **검증 품질·승차 추이·누락 현황·다운로드 결과**가 함께 갱신되는 웹 대시보드를 제작하세요.

## 입력 데이터

- `data/metro_hourly_raw.csv`: 교육용 가상 시간별 관측 데이터
- `data/stations.json`: 역사와 노선 기준정보
- `data/rail_policy.json`: 날짜 범위, 시간 간격, KST 규칙

입력 파일은 수정하지 않습니다. `boardings`는 **역사 승차 기록**이며 열차 내부 혼잡도를 의미하지 않습니다.

## 요구사항

1. **검증:** 미등록 역사, 잘못된 날짜·시간, 음수 승차·지연, 유효하지 않은 관측 횟수, 같은 역사·같은 시각 중복을 탐지합니다.
2. **중복 처리:** 중복 슬롯은 임의로 하나를 채택하지 않고 해당 슬롯에 속한 모든 기록을 제외합니다.
3. **관측 완전성:** 입력 자체가 없는 시간대를 그리드로 복원하며, `boardings = 0`과 결측 슬롯을 구분합니다.
4. **동적 필터:** 여러 역사 선택 및 날짜 범위 변경 시 수치·그래프·품질 보고서를 같은 조건으로 갱신합니다.
5. **KPI:** 총승차 수, 유효 슬롯 수, 예정 슬롯 수, 관측률, 누락 슬롯 수를 표시합니다.
6. **그래프:** 날짜별 승차 추이, 역사별 합계, 역사 × 시간대 Heatmap을 제공합니다.
7. **다중 페이지:** Overview · Data Quality · Exports를 `st.navigation()` 및 `st.Page()`로 구성합니다.
8. **업로드(선택):** CSV 파일을 업로드한 경우 확장자뿐 아니라 필수 열·크기·데이터 내용도 검사합니다. 3MB 이내로 제한합니다.
9. **다운로드:** 현재 필터 조건으로 검증된 행·누락 슬롯 정보를 CSV로 저장합니다.
10. **상태:** 저장한 선택 조건을 사용자 Session State로 관리하고, 다른 사용자의 상태와 혼합하지 않습니다.
11. **재현성:** 데이터 로드·검증·집계는 UI와 독립된 함수로 작성하고 자동 테스트를 통과해야 합니다.

## 검증 기준

- 기본 데이터: 예정 관측 **2,352슬롯**, 유효 관측 **2,330슬롯**, 누락 또는 제외로 인한 미충족 슬롯 **22개**.
- 입력 오류로 제외된 행: **16행** (중복 10행 포함).
- 전체 기준 승차 합계: **408,183명** (교육용 가상 데이터).
- 역사 선택이 1개 또는 7개여도 정상 출력됩니다.
- 방문자가 아무 역사도 선택하지 않은 경우 빈 상태를 표시합니다.
- 값이 0인 관측이 누락으로 바뀌지 않습니다.
