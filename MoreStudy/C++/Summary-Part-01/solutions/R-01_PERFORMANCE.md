# R-01 — 성능 측정 기록

[← Problems](../problem.md) · [Summary 목차](../README.md)

최소 100,000행의 이벤트 데이터를 동일한 입력 내용으로 여러 차례 처리합니다. 디버그/릴리스 빌드, 입력 건수, 운영체제, 컴파일러와 컴파일 옵션을 기록해 실험 조건을 일치시키세요.

| 입력 데이터 | 처리 시간 | 최대 메모리 사용량 | 비고 |
|---|---|---|---|
| 100,000행 | 직접 측정 | 직접 측정 | 기준 구현 |
| 100,000행 | 직접 측정 | 직접 측정 | 탐색·자료구조를 바꾼 구현 |

**비교 기준:** 주문 ID를 `std::map`으로 관리하는 구현의 탐색 비용은 일반적으로 `O(log N)`이며, 매번 모든 주문을 순차 검색하는 경우 최악에 `O(N)`이 듭니다. 같은 입력에서 두 구현을 측정하고 관찰된 차이를 설명하세요. 계측 환경이 다르면 실제 처리 시간이 달라질 수 있으므로 임의로 예상 숫자를 기입하지 않습니다.

반복 실행 뒤 두 출력 CSV를 비교해 내용이 바뀌지 않는지도 함께 확인하세요. 시간 측정에는 Python의 `time.perf_counter()`나 셸의 `time`을 사용할 수 있고, 메모리는 운영체제의 프로세스 성능 도구로 확인할 수 있습니다.
