# R-01 — 오류 코드 정의서

[← Problems](../problem.md) · [Summary 목차](../README.md)

| 오류 코드 | 사유 |
|---|---|
| `BAD_FIELD_COUNT` | 지정된 필드 수와 다름 |
| `MISSING_FIELD` | 빈 필수 필드 존재 |
| `BAD_AMOUNT` | 금액 정수 파싱 실패 또는 0 이하 |
| `BAD_TYPE` | `PAY`·`REFUND` 외의 유형 |
| `DUPLICATE_ORDER` | 이미 승인된 주문 ID 재등장 |
| `DUPLICATE_EVENT` | 이미 정상 적용된 이벤트 ID 재등장 |
| `UNKNOWN_ORDER` | 존재하지 않는 주문 ID |
| `REFUND_EXCEEDS_PAY` | 누적 결제액에서 이미 환불된 금액을 뺀 금액을 초과하는 환불 |
| `ORDER_EXCEEDED` | 적용 후 순결제액이 주문 금액을 초과함 |
| `AMOUNT_OVERFLOW` | 누적액이 정수 범위를 벗어날 위험 |

검사 우선순위: **필드 수 → 필수값 → ID 중복 → 주문 존재 → 유형 → 금액 → 거래 규칙**. 적용되지 않은 이벤트의 ID는 예약하지 않습니다.

CSV는 쉼표로 분리한 단순 필드만 다루며, ID에 구분자 쉼표나 따옴표를 넣지 않는 입력을 전제로 합니다. UTF-8의 비ASCII 문자는 코드 변경 없이 문자열로 보존합니다.

**결과 파일 보호:** 모범답안은 각 결과를 같은 파일시스템의 임시 파일에 기록한 뒤 이름 바꾸기를 시도합니다. 기존 파일이 있어 교체가 거부되는 환경에서는 `.bak` 백업을 이용하지만 이 대체 경로는 엄밀한 원자적 교체가 아닙니다. 두 결과 파일을 한꺼번에 원자적으로 교체하는 기능도 제공하지 않습니다. 실제 운영용 시스템에서는 대상 OS의 교체 API와 복구 정책, 전원 장애 시 내구성까지 별도로 설계해야 합니다.
