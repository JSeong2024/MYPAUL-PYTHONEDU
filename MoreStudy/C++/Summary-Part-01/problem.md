### B-01 — 배송비 계산기

#### 문제

온라인 상점은 상품 무게와 배송 방식에 따라 배송비를 계산합니다. 무게가 1,000g 이하이면 기본 요금을 적용하고, 이를 초과한 무게에는 500g 단위로 추가 요금을 부과합니다. 특급 배송을 선택하면 별도의 요금도 붙습니다.

상품 무게와 배송 유형을 입력받아 최종 배송비를 계산하는 프로그램을 작성하세요. 허용 범위를 벗어난 입력은 요금을 계산하지 않고 `INVALID`로 처리합니다.

#### 구현 조건

1. 상품 무게 `W`는 1~20,000g의 정수입니다. 범위를 벗어나면 `INVALID`를 출력합니다.
2. 기본 배송비는 3,000원입니다. 1,000g을 초과한 무게에 대해서는 500g마다 500원을 추가하며, 남는 무게는 올림하여 계산합니다.
3. 배송 유형은 일반 배송 `0`, 특급 배송 `1`로 구분합니다. 특급 배송에는 2,000원을 추가합니다.
4. 무게와 배송 유형이 모두 유효할 때만 최종 요금을 출력합니다.

#### INPUT

한 줄에 상품 무게 `W`(g)와 배송 유형 `E`가 공백으로 구분되어 주어집니다.

#### OUTPUT

최종 배송비를 원 단위 정수로 출력합니다. 입력이 유효하지 않으면 `INVALID`를 출력합니다.

#### 입출력 예시

**INPUT**

```text
1200 1
```

**OUTPUT**

```text
5500
```

**NOTE**

초과 무게가 1g만 발생하더라도 추가 요금 500원이 부과됩니다.

**STEP 02 — 초과 무게 계산**

1,000g을 넘는 부분만 따로 구하고, 500g 단위로 올림하는 방법을 생각해 보세요.

</details>

### B-02 — 주차 요금 정산

#### 문제

유료 주차장에서 입차 시각과 출차 시각을 기준으로 주차 요금을 정산하려고 합니다. 최초 30분에는 기본 요금이 적용됩니다. 이후 이용 시간은 10분 단위로 계산하며, 10분이 채 되지 않아도 한 단위로 봅니다.

두 시각은 같은 날의 `HH:MM` 형식으로 주어집니다. 주차 시간을 계산해 요금을 출력하는 프로그램을 작성하세요. 시각이 잘못되었거나 출차 시각이 입차 시각보다 늦지 않으면 `INVALID`를 출력합니다.

#### 구현 조건

1. 입차·출차 시각을 `HH:MM` 형식으로 입력받고, 각각 `00:00`부터 `23:59` 사이인지 확인합니다.
2. 출차 시각은 입차 시각보다 늦어야 합니다. 날짜가 바뀌는 주차는 고려하지 않습니다.
3. 이용 시간 30분까지는 1,000원입니다. 30분을 초과하면 10분마다 500원을 추가하고, 남는 시간은 올림하여 계산합니다.
4. 시각 검증과 요금 계산은 각각 함수로 작성합니다.

#### INPUT

한 줄에 입차 시각과 출차 시각이 `HH:MM HH:MM` 형식으로 주어집니다.

#### OUTPUT

주차 요금을 원 단위 정수로 출력합니다. 시각이 유효하지 않거나 출차 시각이 늦지 않으면 `INVALID`를 출력합니다.

#### 입출력 예시

**INPUT**

```text
09:00 09:31
```

**OUTPUT**

```text
1500
```

**NOTE**

시각을 분 단위 정수로 변환하면 주차 시간과 추가 요금을 계산하기 편리합니다.

**STEP 02 — 추가 요금 계산**

이용 시간에서 기본 30분을 제외한 뒤 10분 단위로 계산해 보세요.

</details>

### B-03 — 시험 점수 요약

#### 문제

한 학급의 시험 결과를 정리하려고 합니다. 학생 수와 각 학생의 점수가 주어졌을 때 최저 점수, 최고 점수, 평균 점수를 구해야 합니다. 점수는 0점부터 100점까지이며, 평균은 소수 첫째 자리까지 표시합니다.

입력된 점수의 통계를 출력하는 프로그램을 작성하세요. 학생 수나 점수가 허용 범위를 벗어나면 통계 대신 `INVALID`를 출력합니다.

#### 구현 조건

1. 학생 수 `N`은 1~100명, 각 학생의 점수는 0~100점입니다.
2. 반복문을 사용해 점수의 합계와 최솟값·최댓값을 구합니다.
3. 결과는 `MIN`, `MAX`, `AVG` 순서로 한 줄씩 출력합니다. 평균은 소수 첫째 자리까지 표시합니다.
4. 잘못된 값이 하나라도 있으면 통계 결과를 출력하지 않고 `INVALID`를 출력합니다.

#### INPUT

첫째 줄에 학생 수 `N`, 둘째 줄에 `N`개의 점수가 공백으로 구분되어 주어집니다.

#### OUTPUT

`MIN`, `MAX`, `AVG`를 각각 한 줄에 출력합니다. 평균은 소수 첫째 자리까지 표시하며, 잘못된 입력은 `INVALID`로 처리합니다.

#### 입출력 예시

**INPUT**

```text
4
60 100 80 60
```

**OUTPUT**

```text
MIN 60
MAX 100
AVG 75.0
```

**NOTE**

평균을 구할 때는 정수 나눗셈으로 소수 부분이 사라지지 않도록 주의하세요.

**STEP 02 — 평균 형식 확인**

합계를 누적한 뒤 평균을 구하세요. 소수 첫째 자리 출력과 정수 나눗셈을 구분해야 합니다.

</details>

### B-04 — 상품 코드 검색

#### 문제

매장 상품 목록에는 상품 코드, 가격, 재고 수량이 기록되어 있습니다. 직원은 상품 코드를 입력해 해당 상품의 정보를 조회하려고 합니다.

상품 목록을 입력된 순서대로 검색하고, 코드가 정확히 일치하는 상품의 정보를 출력하는 프로그램을 작성하세요. 찾는 상품이 없으면 `NOT_FOUND`를 출력합니다.

#### 구현 조건

1. 상품의 코드·가격·재고 수량을 하나의 구조체로 표현합니다.
2. 상품 코드는 대소문자를 구분하며, 입력된 코드와 정확히 일치하는 항목을 검색합니다.
3. 상품을 찾으면 코드·가격·재고 수량을 출력합니다. 목록이 비었거나 일치하는 코드가 없으면 `NOT_FOUND`를 출력합니다.
4. 검색과 결과 출력을 별도의 함수로 작성하고, 검색 실패 시 유효하지 않은 인덱스에 접근하지 않도록 합니다.

#### INPUT

첫째 줄에 상품 수 `N`, 다음 `N`줄에 `코드 가격 재고`가 주어집니다. 마지막 줄에는 검색할 상품 코드가 주어집니다.

#### OUTPUT

일치하는 상품을 찾으면 `코드 가격 재고`를 한 줄에 출력합니다. 찾지 못하면 `NOT_FOUND`를 출력합니다.

#### 입출력 예시

**INPUT**

```text
3
P01 1200 4
P02 700 0
P03 2000 9
P02
```

**OUTPUT**

```text
P02 700 0
```

**NOTE**

상품의 재고가 0이어도 등록된 상품이라면 검색 결과에 포함됩니다.

**STEP 02 — 검색 실패 처리**

검색하지 못한 경우에도 안전하게 결과를 반환할 수 있도록 함수의 반환 방식을 정하세요.

### B-05 — 도서 대출 상태 관리

#### 문제

작은 도서관에서 같은 제목의 책을 여러 권 보유하고 있습니다. 책을 빌려줄 때는 대출 가능한 수량을 한 권 줄이고, 반납받으면 한 권 늘립니다. 다만 남은 책이 없으면 대출할 수 없고, 대출된 책이 없다면 반납도 받을 수 없습니다.

`BORROW`와 `RETURN` 명령을 순서대로 처리하는 도서 관리 클래스를 작성하세요. 각 명령의 성공 여부와 남은 수량을 출력해야 합니다.

#### 구현 조건

1. 도서 제목, 전체 보유 수량, 현재 대출 가능한 수량을 관리하는 클래스를 작성합니다.
2. `BORROW`는 대출 가능한 책이 있을 때만 성공하며, 성공하면 남은 수량을 1 줄입니다.
3. `RETURN`은 대출된 책이 있을 때만 성공하며, 성공하면 남은 수량을 1 늘립니다.
4. 실패한 명령은 수량을 변경하지 않습니다. 남은 수량은 항상 0 이상이고 전체 보유 수량 이하여야 합니다.

#### INPUT

첫째 줄에 도서 제목(공백 없음)과 전체 보유 수량 `T`, 둘째 줄에 명령 수 `N`이 주어집니다. 다음 `N`줄에는 `BORROW` 또는 `RETURN`이 한 줄씩 주어집니다.

#### OUTPUT

각 명령을 처리한 뒤 `OK 남은수량` 또는 `FAIL 남은수량`을 한 줄씩 출력합니다.

#### 입출력 예시

**INPUT**

```text
Demo 1
4
BORROW
BORROW
RETURN
RETURN
```

**OUTPUT**

```text
OK 0
FAIL 0
OK 1
FAIL 1
```

**NOTE**

대출이나 반납에 실패해도 이후 명령은 계속 처리합니다. 실패한 명령은 남은 수량에 영향을 주지 않습니다.

**STEP 02 — 명령 실패 처리**

대출·반납이 불가능한 경우에는 수량을 바꾸지 않고 `FAIL`을 출력하세요.

### B-06 — 일일 로그 분류

#### 문제

하루 동안 기록된 애플리케이션 로그에서 정보(`INFO`), 경고(`WARN`), 오류(`ERROR`)가 몇 번 발생했는지 확인하려고 합니다. 로그 파일에는 한 줄에 하나씩 `LEVEL|메시지` 형식의 기록이 들어 있습니다.

파일을 처음부터 끝까지 읽어 레벨별 건수를 출력하는 프로그램을 작성하세요. 알 수 없는 레벨이나 구분자 `|`가 없는 행은 `INVALID`로 집계합니다. 파일을 열지 못했다면 다른 결과를 출력하지 않고 `OPEN_ERROR`만 출력합니다.

#### 구현 조건

1. 표준 입력으로 전달된 파일 경로를 이용해 로그 파일을 엽니다.
2. 파일을 한 줄씩 읽고 `INFO`, `WARN`, `ERROR`의 발생 횟수를 각각 집계합니다.

### C-02 — 센서 장애 보고서

#### 상황 및 배경

건물에 설치된 센서들이 측정값을 중앙 시스템으로 전송합니다. 기록에는 장치 ID와 순번이 함께 저장됩니다. 하지만 통신 지연이나 재전송 때문에 순번이 뒤바뀐 기록이 들어오기도 합니다.

`readings.csv`를 순서대로 처리해 장치별 상태 보고서와 거부 목록을 생성하세요. 한 장치에서 오류가 발생하더라도 다른 장치의 기록은 계속 처리합니다.

### R-01 — 흩어진 정산 기록의 진실

#### 의뢰 배경

서로 다른 시스템에서 출력된 정산 결과가 서로 일치하지 않아 감사(Audit) 팀에 비상이 걸렸습니다. 원본 데이터인 주문 파일과 결제·환불 이벤트 파일은 남아 있지만, 내부에는 중복 이벤트와 훼손된 비정상 행들이 뒤섞여 있어 기존 담당자조차 어떤 기록이 실제로 반영되었는지 설명하지 못하고 있습니다. 데이터의 무결성과 신뢰성을 회복할 수 있는 **결정론적(Deterministic) 정산 검증 프로그램**을 재작성하여 검증 가능한 최종 결과를 납품해야 합니다.

#### 요구사항 및 작업 범위 (Requirements & Scope)

1. **입력 데이터 로드**: `orders.csv`와 `events.csv`를 UTF-8 인코딩(헤더 없음) 기준으로 파싱합니다.
2. **오류 로깅(Validation)**: 필수 필드 누락, 타입 오류, 0 이하 금액 등 유효하지 않은 행을 `rejected.csv`에 **파일명, 원본 행 번호, 표준 오류 코드**로 기록합니다.
3. **주문 중복 제어(Idempotency)**: 주문 ID는 유일해야 합니다. 중복 주문은 `DUPLICATE_ORDER`로 거부하며 최초의 유효 주문만 반영합니다.
4. **이벤트 중복 제어**: 이벤트 ID는 최초로 정상 승인된 것만 적용하며, 이후 다시 등장하면 `DUPLICATE_EVENT`로 거부합니다.
5. **비즈니스 규칙 검증**: 알 수 없는 주문(`UNKNOWN_ORDER`), 누적 결제액을 초과하는 환불(`REFUND_EXCEEDS_PAY`), 주문 금액을 초과하는 순결제액(`ORDER_EXCEEDED`)을 거부합니다.
6. **이벤트 순서 및 불변성**: 이벤트는 입력 파일의 **기록 순서대로** 적용하며, 거부한 이벤트는 금액과 이벤트 ID 사용 상태를 변경하지 않습니다.
7. **정렬 및 출력 규격**: 정산 보고서는 **주문 ID 오름차순**, 오류 보고서는 **파일명·원본 행 번호 오름차순**으로 출력합니다.
8. **결과 재현성(Deterministic)**: 전체 순결제액 합계, 미정산 주문 수와 오류 건수를 함께 기록하며, 동일한 입력을 재처리하면 내용이 완전히 같은 결과 파일을 만들어야 합니다.
9. **안전한 파일 I/O(Atomic Write)**: 같은 파일시스템의 임시 경로에 먼저 기록하고 성공 여부를 확인한 뒤 대상 결과를 교체합니다. 교체 실패와 복구 방법을 명시하고, 플랫폼별 파일 교체 동작을 고려합니다.
10. **성능 분석 및 비교**: 기준 구현 완료 후 10만 행 이상의 데이터를 사용해 처리 시간과 메모리 사용량을 비교하고, 탐색 자료구조와 알고리즘 선택 근거를 작성합니다.

#### INPUT

orders.csv: 주문 ID,주문 금액. events.csv: 이벤트 ID,주문 ID,PAY/REFUND,금액. 두 파일 모두 헤더 없는 UTF-8 텍스트로 제공됩니다.

#### OUTPUT

settlement.csv(주문 ID,주문 금액,순결제액,미정산액)와 rejected.csv(파일명,원본 행번호,오류코드)를 생성합니다. 전체 합계와 건수도 출력합니다.

**입력 파일 구조**

| 파일 | 필드 |
|---|---|
| `orders.csv` | 주문 ID(문자열), 주문 금액(양의 원 단위 정수) |
| `events.csv` | 이벤트 ID, 주문 ID, 유형(`PAY`/`REFUND`), 금액(양의 원 단위 정수) |

**출력 파일 구조**

| 파일 | 필드 |
|---|---|
| `settlement.csv` | 주문 ID, 주문 금액, 순결제액, 미정산액 |
| `rejected.csv` | 파일명, 원본 행 번호, 오류 코드 |

미정산액은 주문 금액에서 순결제액을 뺀 값입니다. 오류 보고서는 파일명·행 번호 오름차순이며, 행 번호는 1부터 시작합니다. 콘솔에는 전체 순결제액 합계, 미정산 주문 수, 오류 건수를 기록합니다.

#### 입출력 예시

**INPUT**

```text
[orders.csv]
A01,10000

[events.csv]
E01,A01,PAY,7000
E02,A01,REFUND,2000
E01,A01,PAY,7000
```

**OUTPUT**

```text
[settlement.csv]
A01,10000,5000,5000

[rejected.csv]
events.csv,3,DUPLICATE_EVENT
```

- **목표:** 재현 가능한 기준 구현을 먼저 완성하고 10만 행 이상 데이터에서 병목을 측정합니다.
- **납품 파일:** 소스 코드, `settlement.csv`, `rejected.csv`
- **문서 자료:** 오류 코드 정의서, 처리 시간·메모리 사용량·알고리즘 선택 근거 메모
