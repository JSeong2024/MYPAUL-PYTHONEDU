# 네트워크 코드 검증과 보안 경계

[← Chapter 18](../README.md)

Chapter 18의 예제는 외부에 공개할 서버 구현체가 아님. 로컬 소켓 프로그래밍, 프로토콜 검증, 안전한 메모리 사용을 학습하기 위한 자료임.

## 반드시 구분할 것

* **Loopback은 암호화·인증을 제공하지 않음.** 같은 시스템의 다른 프로세스가 접근할 수도 있음.
* **TCP는 데이터의 순서·재전송을 제공**하지만, 애플리케이션 명령 처리의 중복 방지나 세션 인증은 제공하지 않음.
* `SO_RCVTIMEO`는 하나의 수신 호출의 타임아웃일 수 있으며, 전체 트랜잭션의 절대 기한이 아님.
* **수신 길이 검증 후 할당**: 4바이트 길이가 4096을 넘으면 본문 버퍼를 생성하지 않고 거부함.
* `std::from_chars`는 `end == last` 확인까지 수행해야 전체 숫자 검증임.
* 길이가 있는 바이트 버퍼를 널 종료 문자열로 취급하지 않음.
* 클라이언트가 정한 원시 파일 경로·셸 명령 등을 그대로 실행하지 않음.
* 요청 재시도는 중복 결제 같은 부작용을 일으킬 수 있으므로 멱등성과 식별자 설계를 함께 검토함.

## 운영 서버 확장 시 필요한 기능

1. TLS와 인증(서버/사용자/클라이언트), 권한 검증
2. 동시 접속 수·요청 크기·속도 제한
3. Backpressure, 작업 큐 제한, 연결 수명 관리
4. 메시지 검증·에러 응답과 민감 정보 비노출 로그
5. Graceful Shutdown 및 실제 전체 Deadline
6. 프로토콜 버전 관리와 회귀 테스트

별도 인증이 없다면 포트를 외부 인터페이스에 바인딩하지 않는 것을 기본으로 함.
