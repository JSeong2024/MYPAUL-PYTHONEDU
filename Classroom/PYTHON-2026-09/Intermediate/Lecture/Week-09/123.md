# 자동화 프로그램의 개념과 원리

폴더에 파일이 다섯 개 있다면 이름을 하나씩 확인해 표에 적을 수 있습니다. 파일이 백 개로 늘어나고 같은 목록을 매주 만들어야 한다면 어떨까요? 사람이 하는 일을 순서대로 적어 보면, **폴더를 살펴보고, 확장자를 확인하고, 규칙을 적용해, 결과를 표에 적는 일**이 반복됩니다. 이 절차를 Python 코드로 옮겨 보겠습니다.

이번 수업의 목표는 자동화할 작업을 **시작 조건, 입력, 처리 규칙, 출력**으로 나누어 설명하고, 폴더를 탐색해 파일 분류 보고서를 만드는 프로그램을 직접 실행하는 것입니다.

## 1. 들어가며

변수, 조건문, 반복문을 사용할 수 있다면 실습을 시작할 수 있습니다. 아래 개념은 익숙한 문법을 실제 작업에 연결하는 데 필요합니다.

### 1.1 입력과 출력

택배 분류 작업에는 들어오는 상자가 있고, 분류를 마친 뒤에는 배송지별로 정리된 상자가 나옵니다. 프로그램에도 작업에 필요한 **입력**과 작업이 끝났을 때 얻는 **출력**이 있습니다.

파일 분류 프로그램에서 입력은 **탐색할 폴더와 분류 규칙**입니다. 출력은 **파일별 분류 결과를 담은 보고서**입니다. 처리한 파일 개수를 터미널에 표시한다면 그 메시지도 출력입니다.

함수 수준에서도 입력과 출력을 구분할 수 있습니다. `collect_rows(folder)`는 `folder`를 전달받아 보고서에 넣을 행을 `return`으로 돌려줍니다. 이렇게 얻은 목록은 화면에 표시할 수도 있고 CSV로 저장할 수도 있습니다. `print(rows)`를 사용하면 목록을 화면으로 확인할 수 있지만, 호출한 쪽에서 그 목록을 사용하려면 함수가 값을 반환해야 합니다.

### 1.2 파일 시스템과 경로

파일 시스템은 운영체제가 파일과 폴더를 저장하고 찾는 방식입니다. 폴더 안에는 파일도 있고 다른 폴더도 있습니다. 따라서 폴더를 탐색할 때는 발견한 항목이 파일인지 확인하는 과정이 필요합니다.

| 용어 | 예시 | 의미 |
|---|---|---|
| **절대 경로** | `D:\수업\sample_files\과학\발표.PDF` | 드라이브 시작점부터 파일의 위치를 나타냅니다. |
| **상대 경로** | `과학/발표.PDF` | 이 예시에서는 `sample_files` 폴더를 기준으로 파일의 위치를 나타냅니다. |
| **파일명** | `발표.PDF` | 경로에서 마지막에 오는 파일의 이름입니다. |
| **확장자** | `.PDF` | 파일명 끝에 붙은 형식 표시입니다. Python의 `Path.suffix`에는 앞의 점도 포함됩니다. |

`과학/발표.PDF`와 `동아리/발표.PDF`는 파일명이 같습니다. 표에 `발표.PDF`만 두 번 적으면 구분하기 어렵지만, **탐색 기준 폴더로부터의 상대 경로**를 함께 기록하면 어느 파일인지 알 수 있습니다.

### 1.3 리스트와 딕셔너리

**리스트**는 순서대로 항목을 모을 때 사용합니다. 파일을 찾을 때마다 보고서에 들어갈 한 행을 리스트에 추가할 수 있습니다.

**딕셔너리**는 키에 연결된 값을 찾을 때 사용합니다. 분류 규칙은 확장자를 키로, 카테고리를 값으로 두면 편리합니다.

```python
rules = {".pdf": "문서", ".png": "이미지"}

print(rules.get(".pdf", "미분류"))  # 문서
print(rules.get(".zip", "미분류"))  # 미분류
```

`rules.get(키, 기본값)`은 키가 있으면 연결된 값을 반환하고, 없으면 기본값을 반환합니다. 이 예시에서 `미분류`는 규칙에 없는 파일을 목록에 어떻게 표시할지 정한 값입니다.

### 1.4 라이브러리와 API

라이브러리는 여러 프로그램에서 재사용할 수 있도록 기능을 모아 둔 도구입니다. 예를 들어 CSV 파일을 만들 때 이름에 쉼표가 들어 있는 파일을 어떻게 기록할지 직접 처리할 수도 있습니다. Python의 `csv` 모듈을 사용하면 각 칸의 값을 넘기는 것만으로 CSV 형식에 맞게 저장할 수 있습니다.

**API**는 그 도구에 일을 요청하는 약속입니다. 도서관 대출 창구에서는 책과 대출증을 건네고 처리 결과를 받습니다. 비슷하게 `writer.writerow([...])`에 한 행을 전달하면 CSV 작성기가 그 행을 기록합니다. 어떤 이름으로 호출하고, 어떤 값을 넘기며, 어떤 결과를 얻는지가 API를 사용하는 데 필요한 정보입니다.

API는 라이브러리 함수에도 있고 인터넷 서비스에도 있습니다. 이번 실습에서는 Python에 포함된 `pathlib`과 `csv`의 API를 사용하므로 인터넷 연결이나 별도 패키지 설치가 필요하지 않습니다.

### 1.5 예외 처리

작업 절차가 올바르더라도 필요한 폴더가 없거나 결과 파일을 쓸 권한이 없을 수 있습니다. 이런 상황을 예상하고 처리해야 사용자가 다음에 무엇을 할지 알 수 있습니다.

이번 예제에서는 입력 폴더가 있는지 먼저 확인합니다. 보고서가 이미 있는 경우에는 기존 파일을 보존하고 다른 이름으로 옮긴 뒤 다시 실행하라고 안내합니다. 이러한 처리는 파일을 분류하는 규칙만큼 중요합니다. 자동화 프로그램은 같은 작업을 여러 번 수행하므로, 예상 가능한 실패도 작업 절차에 포함해야 합니다.

#### `try`와 `except` 사용하기

`try`에는 예외가 발생할 수 있는 코드를 넣습니다. `except`에는 **어떤 예외를 처리할지**와 **그 예외가 발생했을 때 무엇을 할지**를 적습니다.

아래 코드는 입력받은 글자를 정수로 바꿉니다. `3`은 정수로 바꿀 수 있지만, `세 개`는 바꿀 수 없습니다.

```python
text = input("파일 개수를 정수로 입력하세요. ")

try:
    count = int(text)
except ValueError:
    print("숫자로 입력해 주세요. 예를 들어 3을 입력하세요.")
else:
    print(f"파일 {count}개를 처리합니다.")
```

| 입력 | 실행 흐름 | 출력 |
|---|---|---|
| `3` | `int(text)`가 성공해 `else`를 실행합니다. | `파일 3개를 처리합니다.` |
| `세 개` | `int(text)`에서 `ValueError`가 발생해 `except`를 실행합니다. | `숫자로 입력해 주세요. 예를 들어 3을 입력하세요.` |

`else`는 `try` 블록이 예외 없이 끝났을 때 실행됩니다. 꼭 써야 하는 부분은 아닙니다. 이 예제에서는 정수 변환에 성공했을 때만 `count`에 값이 들어가므로 완료 메시지를 `else`에 둡니다.

#### 파일 쓰기에서 예외 처리하기

(정수 변환) 예제에서는 `int()`에서 예외가 발생했습니다. 파일 작업에서는 `open()`도 예외를 발생시킬 수 있습니다. `"x"` 모드는 새 파일을 만들 때 사용합니다. 같은 이름의 파일이 있으면 `FileExistsError`가 발생하고, 기존 파일의 내용은 그대로 남습니다.

```python
try:
    with open("file_report.csv", "x", encoding="utf-8") as report:
        report.write("파일명\n")
except FileExistsError:
    print("보고서가 이미 있습니다. 기존 보고서의 이름을 바꾼 뒤 다시 실행하세요.")
else:
    print("새 보고서를 만들었습니다.")
```

`file_report.csv`가 없는 폴더에서 코드를 두 번 실행해 봅시다. 첫 번째에는 파일을 만들고 `else`의 완료 메시지를 출력합니다. 두 번째에는 `open()`에서 예외가 발생해 `report.write()`를 건너뛰고 `except`의 안내를 출력합니다.

#### 실습 · 파일 목록을 CSV로 저장하기

아래 코드를 `folder_report.py`로 저장합니다. 터미널에서 이 코드가 있는 폴더로 이동한 뒤 실행하면, 현재 작업 폴더의 `sample_files`에서 바로 아래에 있는 파일의 이름을 모아 `file_report.csv`에 기록합니다.

이전 미니 예제도 같은 이름의 CSV를 만듭니다. 미니 예제를 먼저 실행했다면 그 보고서의 이름을 바꾼 뒤 실습을 시작합니다.

```python
import csv
from pathlib import Path


def main():
    folder = Path("sample_files")
    report = Path("file_report.csv")

    try:
        # 작업을 시작하기 전에 입력 폴더를 확인합니다.
        if not folder.is_dir():
            print("sample_files 폴더가 없습니다. 실습 폴더에 만들어 주세요.")
            return

        # 목록을 수집한 뒤 보고서 쓰기를 시작합니다.
        names = sorted(path.name for path in folder.iterdir() if path.is_file())

        with report.open("x", encoding="utf-8-sig", newline="") as output:
            writer = csv.writer(output)
            writer.writerow(["파일명"])
            for name in names:
                writer.writerow([name])

    except FileExistsError:
        print("보고서가 이미 있습니다. 기존 보고서의 이름을 바꾼 뒤 다시 실행하세요.")
    except PermissionError:
        print("폴더를 읽거나 보고서를 저장할 권한이 없습니다. 접근 권한을 확인하세요.")
    except OSError as error:
        print(f"파일을 처리하는 중 오류가 발생했습니다. {error}")
    else:
        print(f"파일 {len(names)}개의 목록을 {report}에 저장했습니다.")


if __name__ == "__main__":
    main()
```

**`if`는 폴더가 있는지 미리 확인하고, `try`와 `except`는 파일 작업 중 발생하는 예외를 처리합니다.** 폴더가 없으면 안내를 출력하고 `return`으로 함수를 끝냅니다. 폴더가 있어도 실행 도중 접근 권한이 바뀌거나, 같은 이름의 보고서가 존재해 쓰기가 실패할 수 있습니다.

`FileExistsError`와 `PermissionError`는 모두 `OSError`의 하위 유형입니다. Python은 발생한 예외에 맞는 `except`를 위에서부터 찾습니다. 넓은 범위의 `except OSError`를 먼저 두면 앞의 두 상황도 같은 문구로 처리되므로, 구체적인 예외를 먼저 적습니다.

| 실행 조건 | 확인할 결과 |
|---|---|
| `sample_files` 폴더 없이 실행 | 폴더를 만들어 달라는 안내가 나오고 보고서는 생기지 않습니다. |
| `sample_files`에 `발표.pdf`와 `메모.txt`를 넣고 실행 | `file_report.csv`가 생성되고 파일 2개를 기록했다는 메시지가 나옵니다. |
| 보고서를 그대로 둔 채 다시 실행 | 이미 보고서가 있다는 안내가 나오고 기존 CSV 내용이 유지됩니다. |


## 2. 본론 1 · 자동화 프로그램이란 무엇인가?

**자동화 프로그램은 사람이 반복해서 수행하던 절차를 정해 둔 조건과 규칙에 따라 대신 처리하는 프로그램**입니다. 사용자가 버튼을 누르거나 명령을 입력해 시작할 수도 있고, 정해진 시각이나 파일이 추가되는 등의 사건을 계기로 시작할 수도 있습니다.

예를 들어 폴더의 파일 목록을 만드는 작업을 비교해 봅시다.

| 작업 | 사람이 수행할 때 | 프로그램으로 자동화할 때 |
|---|---|---|
| 파일 찾기 | 폴더와 하위 폴더를 하나씩 엽니다. | 기준 폴더 아래의 항목을 차례로 탐색합니다. |
| 분류하기 | 파일명 끝을 보고 카테고리를 판단해 적습니다. | 확장자를 읽고 같은 분류 규칙을 적용합니다. |
| 결과 남기기 | 표에 한 줄씩 입력합니다. | 수집한 결과를 CSV 파일에 기록합니다. |
| 다음번에 다시 수행하기 | 처음부터 같은 절차를 반복합니다. | 같은 프로그램을 새 입력으로 다시 실행합니다. |

여기서 `for`문은 **항목마다 같은 일을 반복하는 수단**입니다. 자동화할 작업을 설계할 때는 반복문에 들어갈 코드에 앞서 **언제 시작할지, 무엇을 반복할지, 어떤 기준으로 판단할지, 결과를 어디에 남길지**를 정해야 합니다.

### 2.1 자동화가 필요한 이유

파일 수가 늘어날수록 사람이 하나씩 확인하는 데 시간이 더 걸립니다. 보고서를 매주 만들면 같은 시간이 반복해서 듭니다. 이처럼 **대상이 많거나 자주 되풀이되는 작업**에 자동화를 적용하면 절약되는 시간이 쌓입니다.

자동화는 결과의 **일관성**도 높여 줍니다. `.pdf`와 `.PDF`를 항상 소문자로 맞춘 뒤 분류하면 사람이 처리할 때 생기는 표기 차이를 줄일 수 있습니다. 반대로 규칙을 잘못 정하면 여러 파일에 같은 오류가 적용됩니다. 그래서 처음에는 작은 샘플로 결과를 확인하고, 규칙으로 판단하기 어려운 항목의 처리 방법도 정해 두는 것이 좋습니다.

확장자는 파일의 **이름에 담긴 정보**입니다. `.pdf`를 `문서`로 분류할 수는 있지만, 이름만 보고 그 파일이 과학 발표 자료인지 동아리 안내문인지 판단할 수는 없습니다. 이런 경우 사용자가 직접 카테고리를 지정하도록 하고, 그 값을 자동 규칙보다 먼저 적용할 수 있습니다.

### 2.2 일상과 실무의 자동화 사례

| 상황 | 시작 조건 | 처리 규칙과 결과 |
|---|---|---|
| **과제 제출 현황 확인** | 교사가 스크립트를 실행합니다. | 제출 폴더의 파일명을 학생 명단과 비교해 확인이 필요한 학생을 표로 정리합니다. |
| **다운로드 폴더 정리** | 사용자가 `새로고침`을 누릅니다. | 확장자별 규칙을 적용해 앱 목록에 문서, 이미지, 압축 파일을 구분해 표시합니다. |
| **일일 매출 집계** | 영업 종료 시각이 됩니다. | 당일 거래 CSV의 금액을 더하고 지점별 합계를 보고서로 저장합니다. |
| **기록 파일 확인** | 하루에 한 번 정해진 시각이 됩니다. | 기록 파일에서 오류가 표시된 줄을 찾아 확인할 항목만 모읍니다. |

## 3. 본론 2 · 실전 예제 — 폴더 분류 보고서 만들기

이 프로그램을 실행하면 `sample_files` 폴더와 그 하위 폴더를 탐색합니다. 각 파일의 확장자를 규칙과 비교하고, **상대 경로·확장자·카테고리**를 `file_report.csv`에 저장합니다. 원본 파일의 위치와 내용은 그대로 유지됩니다.

### 3.1 실습 환경 준비

1. 실습 폴더를 하나 만들고 아래 코드를 `folder_report.py`로 저장합니다.
2. 같은 위치에 `sample_files` 폴더를 만들고, 그 안에 다음 파일을 준비합니다.

| `sample_files` 기준 상대 경로 | 확인할 동작 |
|---|---|
| `과학/발표.PDF` | 대문자 확장자도 PDF로 분류합니다. |
| `동아리/발표.PDF` | 같은 이름의 파일을 상대 경로로 구분합니다. |
| `동아리/준비물.csv` | CSV를 `표 데이터`로 분류합니다. |
| `메모` | 확장자가 없으면 `미분류`로 표시합니다. |
| `사진.png` | PNG를 `이미지`로 분류합니다. |

실습용 파일은 내용이 비어 있어도 됩니다. 이 프로그램은 파일 내용을 열지 않고 파일명과 경로를 사용합니다.

### 3.2 전체 코드

```python
import csv
from pathlib import Path

RULES = {
    ".pdf": "문서",
    ".txt": "문서",
    ".csv": "표 데이터",
    ".png": "이미지",
}


def collect_rows(folder):
    rows = []
    for path in sorted(folder.rglob("*")):
        if not path.is_file():
            continue
        suffix = path.suffix.lower()
        category = RULES.get(suffix, "미분류")
        relative_path = path.relative_to(folder).as_posix()
        rows.append([relative_path, suffix, category])
    return rows


def main():
    folder = Path("sample_files")
    report = Path("file_report.csv")

    if not folder.is_dir():
        print("sample_files 폴더를 찾을 수 없습니다.")
        return

    try:
        rows = collect_rows(folder)
        with report.open("x", encoding="utf-8-sig", newline="") as output:
            writer = csv.writer(output)
            writer.writerow(["상대 경로", "확장자", "카테고리"])
            writer.writerows(rows)
    except FileExistsError:
        print("file_report.csv가 이미 있습니다. 기존 보고서의 이름을 바꾼 뒤 다시 실행하세요.")
    except OSError as error:
        print(f"폴더를 읽거나 보고서를 저장할 수 없습니다. {error}")
    else:
        print(f"파일 {len(rows)}개의 보고서를 저장했습니다. {report}")


if __name__ == "__main__":
    main()
```

### 3.3 코드가 실행되는 순서

아래 줄 번호는 위 코드의 첫 `import`를 1번으로 세며 빈 줄도 포함합니다.

**먼저 사용할 도구와 규칙을 준비합니다.**

| 줄 | 하는 일 |
|---|---|
| **1~2** | `csv`는 표 형식의 파일을 쓰는 데 사용합니다. `Path`는 경로를 다루고 파일이나 폴더인지 확인하는 데 사용합니다. |
| **4~9** | 확장자별 카테고리를 딕셔너리로 정의합니다. 예를 들어 `.pdf`를 조회하면 `문서`가 나옵니다. |

#### 함수 정의와 호출

**24줄의 `def main():`은 `main`이라는 함수를 정의합니다.** 괄호가 비어 있으므로 호출할 때 전달할 값이 없습니다. `main`은 프로그램의 주요 실행 절차를 모아 두는 함수에 자주 붙이는 이름입니다. Python에서는 다른 이름으로 바꾸어도 호출하는 곳에서 같은 이름을 쓰면 됩니다.

Python이 위에서 아래로 읽으면서 **12줄의 `def collect_rows(folder):`와 24줄의 `def main():`을 만나면, 두 함수를 나중에 호출할 수 있도록 정의**합니다. 실제로 폴더를 확인하거나 파일을 탐색하는 작업은 각 함수가 호출될 때 시작합니다.

| 줄 | 코드 | 하는 일 |
|---|---|---|
| **24** | `def main():` | 폴더 확인부터 CSV 저장까지의 절차를 함수로 정의합니다. |
| **46** | `if __name__ == "__main__":` | 이 파일을 직접 실행했는지 확인합니다. |
| **47** | `main()` | 조건이 참일 때 함수를 호출합니다. 이때 25줄부터 들여쓴 작업이 실행됩니다. |

#### `if __name__ == "__main__":`을 사용하는 이유

`python folder_report.py`로 파일을 직접 실행하면, 맨 아래에 `main()` 한 줄만 있어도 보고서를 만들 수 있습니다. 이 예제에서는 `collect_rows()`를 Tkinter 같은 다른 코드에서도 가져다 쓸 수 있도록, 파일을 직접 실행했을 때만 `main()`을 호출하는 조건을 붙였습니다.

예를 들어 Tkinter 코드의 첫 부분에 `from folder_report import collect_rows`를 쓰면, Python은 `folder_report.py`를 불러오면서 파일 끝의 코드도 확인합니다. 그 자리에 `main()`만 있으면 폴더 선택창을 열기도 전에 보고서 작성이 시작됩니다. 조건을 붙여 두면 화면을 먼저 띄우고, 사용자가 **폴더 선택** 버튼을 눌렀을 때 탐색 함수를 호출할 수 있습니다.

`__name__`은 Python이 각 파일에 설정하는 변수입니다. 이 파일을 직접 실행하면 그 값은 `"__main__"`입니다. 따라서 46줄의 조건이 참이 되고, 47줄에서 `main()`을 호출합니다.

| 사용하는 방법 | `__name__`의 값 | 실행 결과 |
|---|---|---|
| `python folder_report.py` | `"__main__"` | `main()`을 호출해 보고서 작성을 시작합니다. |
| `from folder_report import collect_rows` | `"folder_report"` | 모듈의 함수와 규칙을 준비합니다. 46줄의 조건이 거짓이므로 `main()`은 호출되지 않습니다. 가져온 `collect_rows()`는 필요할 때 호출할 수 있습니다. |

#### 마지막 두 줄을 빼면 어떻게 되나요?

`if` 조건을 빼는 것과 `main()` 호출까지 빼는 것은 결과가 다릅니다. `def main():`은 그대로 두고 파일 끝만 바꿔 비교해 봅시다.

| 파일 끝에 있는 코드 | 직접 실행 | 다른 파일에서 처음 불러오기 |
|---|---|---|
| `if __name__ == "__main__":` 아래에 `main()` | 보고서 작성을 시작합니다. | 함수를 불러옵니다. 보고서는 만들지 않습니다. |
| 들여쓰기 없는 `main()` 한 줄 | 보고서 작성을 시작합니다. | 파일을 읽는 과정에서 `main()`도 실행되어 보고서 작성을 시작합니다. |
| 호출 없이 함수 정의까지만 작성 | 함수만 정의하므로 보고서가 생기지 않습니다. | 함수를 불러온 뒤 필요할 때 호출할 수 있습니다. |

**직접 확인해 봅시다.** `folder_report.py`와 같은 폴더에 `check_import.py`를 만들고 아래 코드를 저장합니다. `sample_files` 폴더를 준비하고, 각 실행 전에 기존 `file_report.csv`가 있으면 이름을 바꿉니다.

```python
from folder_report import collect_rows

print("함수를 불러왔습니다.")
```

1. 원래 코드대로 둔 상태에서 `python check_import.py`를 실행합니다. `함수를 불러왔습니다.`만 표시되고 보고서는 생기지 않습니다.
2. `folder_report.py`의 마지막 두 줄을 들여쓰기 없는 `main()` 한 줄로 바꾼 뒤, 같은 명령을 다시 실행합니다. **보고서 저장 메시지가 먼저 나오고**, 이어서 `함수를 불러왔습니다.`가 표시됩니다. `check_import.py`에는 보고서를 만들라는 코드가 없어도 CSV가 생성됩니다.

**`main()`은 입력 위치를 확인합니다.**

| 줄 | 하는 일 |

| **28~30** | `sample_files`가 폴더인지 확인합니다. 폴더를 찾지 못하면 안내를 출력하고 `return`으로 작업을 끝냅니다. |
| **32~33** | `try` 안에서 탐색과 저장을 시작합니다. 먼저 `collect_rows(folder)`를 호출해 CSV에 넣을 행을 얻습니다. |

**`collect_rows()`는 파일 하나를 보고서 한 행으로 바꿉니다.**

| 줄 | 하는 일 |
|---|---|
| **12~13** | 탐색할 폴더를 매개변수로 받고, 결과를 넣을 빈 리스트를 만듭니다. |
| **14** | `rglob("*")`로 하위 폴더를 포함한 항목을 찾습니다. `sorted()`를 사용해 같은 목록을 다시 처리할 때 행 순서를 일정하게 유지합니다. |
| **15~16** | 발견한 항목이 파일이 아니면 `continue`로 다음 항목으로 넘어갑니다. 이 조건이 있으므로 폴더 자체는 보고서에 들어가지 않습니다. |
| **17** | `path.suffix`로 얻은 확장자를 소문자로 바꿉니다. `발표.PDF`에서 `.PDF`가 나오면 `.pdf`로 바뀝니다. |

| **20~21** | 파일 한 개의 정보를 한 행으로 추가합니다. 모든 항목을 확인한 뒤 완성된 리스트를 `main()`으로 반환합니다. |

## 4. 핵심 요약

- **자동화**는 정해 둔 절차를 프로그램이 반복 수행하게 만드는 것입니다. 실행 버튼이나 명령도 작업의 시작 조건이 될 수 있습니다.
- 작업을 설계할 때는 **시작 조건, 입력, 처리 규칙, 출력**을 각각 정합니다.
- 파일을 탐색할 때는 폴더와 파일을 구분합니다. **기준 폴더와 상대 경로**를 함께 사용하면 이름이 같은 파일도 구별할 수 있습니다.
- 딕셔너리에 분류 규칙을 넣고 기본값을 정해 두면, 규칙이 없는 파일도 일관되게 처리할 수 있습니다.
- 탐색과 저장을 구분하면 같은 탐색 함수를 터미널, CSV 보고서, Tkinter 화면에서 재사용할 수 있습니다.
- 작은 샘플로 정상 결과와 예외를 모두 확인합니다. 이번 예제에서 점검할 예외는 **확장자 없음, 입력 폴더 없음, 기존 보고서가 있음**입니다.

### 문제 4 · 응용 — 실행 결과 예측

아래 코드에는 **수동 분류가 있으면 수동 분류를 사용하고, 없으면 자동 규칙을 적용한다**는 조건이 추가되어 있습니다. 출력에 나타날 세 줄을 순서대로 쓰세요.

```python
from pathlib import Path

rules = {".pdf": "문서", ".png": "이미지"}
manual_categories = {"동아리/발표.PDF": "동아리"}
files = ["과학/발표.PDF", "동아리/발표.PDF", "메모"]

for relative_path in files:
    if relative_path in manual_categories:
        category = manual_categories[relative_path]
    else:
        suffix = Path(relative_path).suffix.lower()
        category = rules.get(suffix, "미분류")
    print(relative_path, category)
```

## 6. 정답 및 해설

### 문제 1 · 정답 B

사용자는 버튼으로 작업을 시작합니다. 그 뒤의 폴더 탐색, 규칙 적용, 표 작성은 프로그램이 수행하므로 자동화에 해당합니다.

- **A**에서는 탐색과 분류를 모두 사람이 수행합니다.
- **C**에서는 버튼이 있어도 실제 탐색과 분류가 이루어지지 않습니다.
- **D**에서 프로그램이 담당하는 일은 표 표시입니다. 탐색과 분류는 여전히 사람이 수행합니다.

### 문제 2 · 같은 키를 사용하면 기존 메모가 덮어써집니다

딕셔너리에서 같은 키에 값을 다시 대입하면 이전 값을 새 값으로 바꿉니다. 두 파일 모두 키가 `발표.pdf`라면 나중에 저장한 메모만 남습니다.

하나의 기준 폴더를 관리한다면 `과학/발표.pdf`와 `동아리/발표.pdf`를 각각 키로 사용할 수 있습니다. 여러 기준 폴더의 기록을 한곳에 저장한다면 **기준 폴더별로 기록을 나누고, 그 안에서 상대 경로를 키로 쓰면** 서로 다른 기준 폴더에 같은 상대 경로가 있어도 구분할 수 있습니다.

### 문제 3 · `lower`, `get`

```python
suffix = path.suffix.lower()
category = rules.get(suffix, "미분류")
```

`path.suffix`의 값은 `.PDF`입니다. `.lower()`를 호출하면 규칙의 키와 같은 `.pdf`가 되어 `문서`가 출력됩니다. 소문자로 바꾸지 않으면 `.PDF`와 `.pdf`는 다른 키이므로 `미분류`가 출력됩니다. `rules[suffix]`로 조회하는 경우에는 키가 없는 확장자에서 `KeyError`가 발생하므로, 기본값을 지정할 수 있는 `get()`을 사용합니다.

### 문제 4 · 예상 출력

```text
과학/발표.PDF 문서
동아리/발표.PDF 동아리
메모 미분류
```

1. `과학/발표.PDF`에는 수동 지정이 없습니다. `.PDF`를 `.pdf`로 바꾼 뒤 자동 규칙을 적용해 `문서`가 됩니다.
2. `동아리/발표.PDF`는 상대 경로가 `manual_categories`의 키와 일치합니다. 첫 번째 분기에서 `동아리`가 결정되고, 이 파일에 대해서는 `else`의 자동 규칙을 실행하지 않습니다.
3. `메모`에는 수동 지정도 확장자도 없습니다. `Path("메모").suffix`가 반환하는 빈 문자열을 규칙에서 찾을 수 없으므로 기본값인 `미분류`가 됩니다.
