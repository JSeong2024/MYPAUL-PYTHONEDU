# 5.5. Nested Conditions

**중첩 조건문**

카페에서 주문한 메뉴가 가격표에 있는지 확인합니다. 등록된 메뉴라면 가격을 읽고, 받은 돈이 충분한지 확인합니다. 이렇게 앞의 판단을 통과한 경우에만 다음 판단을 할 때 중첩 조건문을 쓸 수 있습니다.

## 5.5.1. 조건문 안에 조건문 넣기

`if` 블록 안에 또 다른 `if`문을 넣는 구조를 **중첩 조건문**(**Nested Conditional Statement**)이라고 합니다. 안쪽 `if`문은 바깥쪽 `if`문의 실행 블록에 속하므로, 바깥쪽 조건이 참(`True`)일 때만 안쪽 조건을 검사합니다.

```text
if (조건1):
    if (조건2):
        (코드1)
    else:
        (코드2)
else:
    (코드3)
(코드4)
```

> 만약 `조건1`이 참이라면 `조건2`를 검사합니다. 이때 `조건2`도 참이라면 `코드1`을, 거짓이라면 `코드2`를 실행합니다.  
> 반대로 `조건1`이 거짓이라면 안쪽 조건문 전체를 건너뛰고 바깥쪽 `else`의 `코드3`을 실행합니다.

이 예제에서 `코드4`는 어느 분기를 거치든 조건문이 끝난 뒤 실행됩니다. `else`는 같은 깊이에 있는 `if`와 짝을 이룹니다. 안쪽 `if`와 `else`는 공백 네 칸, 그 아래 코드는 공백 여덟 칸을 들여씁니다.

## 5.5.2. 메뉴를 확인한 뒤 결제하기

바깥쪽 조건문에서는 주문한 메뉴가 메뉴판(`menu`)에 등록되어 있는지 먼저 확인합니다. 메뉴가 등록되어 있으면 `menu[item]`으로 가격을 읽어 오고, 이어서 안쪽 조건문에서 손님이 낸 돈과 가격을 비교해 결제를 진행합니다.

```python
menu = {"커피": 4800, "쿠키": 2500}
item = "커피"
paid = 5000

if item in menu:
    price = menu[item]

    if paid >= price:
        change = paid - price
        print(f"결제 완료. 거스름돈은 {change:,}원입니다.")
    else:
        shortage = price - paid
        print(f"{shortage:,}원이 부족합니다.")
else:
    print(f"판매하지 않는 메뉴입니다. ({item})")

print("주문 확인을 마쳤습니다.")
```

**실행 결과**

```text
결제 완료. 거스름돈은 200원입니다.
주문 확인을 마쳤습니다.
```

> `{change:,}`에서 `change`는 출력할 값입니다. `:` 뒤에는 출력 형식을 적고, `,`는 숫자를 세 자리마다 쉼표로 구분합니다. 예를 들어 `1200`은 `1,200`으로 표시됩니다.

변수 `item`과 `paid`의 값을 아래 표처럼 바꾸어 보며 어느 분기가 실행되는지 직접 확인해 보세요.

  <thead>
    <tr><th>주문 메뉴</th><th>받은 돈</th><th>바깥 조건</th><th>안쪽 조건</th><th>첫 출력</th></tr>
  </thead>
  <tbody>
    <tr><td>커피</td><td>5,000원</td><td>참</td><td>참</td><td>결제 완료. 거스름돈은 200원입니다.</td></tr>
    <tr><td>커피</td><td>4,800원</td><td>참</td><td>참</td><td>결제 완료. 거스름돈은 0원입니다.</td></tr>

## 5.5.3. 조건을 묶을 때와 중첩할 때

5.4절에서 배운 논리 연산자 `and`를 사용하면 두 조건을 한 줄로 묶어서 확인할 수도 있습니다. 다음 코드처럼 작성하면 왼쪽의 `item in menu`가 참일 때만 오른쪽의 가격 비교(`paid >= menu[item]`)를 이어서 검사합니다.

```python
menu = {"커피": 4800, "쿠키": 2500}
item = "주스"
paid = 5000

if item in menu and paid >= menu[item]:
    print("결제할 수 있습니다.")
else:
    print("결제할 수 없습니다.")
```

**실행 결과**

```text
결제할 수 없습니다.
```

> `and`는 왼쪽 값이 거짓으로 평가되면 오른쪽을 평가하지 않습니다. 결과를 판단하는 데 필요한 부분까지만 평가하는 방식을 **단락 평가**(**Short-circuit Evaluation**)라고 합니다. 예제에서 `"주스"`는 가격표에 없으므로 `menu[item]`을 조회하지 않습니다.

결제 가능 여부만 알려 줄 때는 `and`로 두 조건을 묶을 수 있습니다. 메뉴가 없을 때와 받은 돈이 부족할 때 다른 안내를 띄우려면 5.5.2절처럼 분기를 나눌 수 있습니다.

<table align="center">
  <thead>
    <tr><th>구분</th><th><code>and</code>로 묶기</th><th>중첩 조건문 쓰기</th></tr>
  </thead>
  <tbody>
    <tr><th>적합한 상황</th><td>두 조건을 모두 충족하는지 확인할 때</td><td>앞 조건을 통과한 뒤 추가 작업이나 판단이 필요할 때</td></tr>
    <tr><th>이 예제의 안내</th><td>두 조건 중 하나라도 거짓이면 같은 메시지를 출력합니다.</td><td>미등록 메뉴와 금액 부족을 구분해 안내합니다.</td></tr>
  </tbody>
</table>

> 중첩이 깊어지면 어느 조건을 통과해야 각 줄이 실행되는지 따라가기 어려워질 수 있습니다. 여러 조건에 같은 안내를 띄운다면 한 조건식으로 묶을 수 있는지 살펴보세요.

## 확인 문제

1. 다음 구조에서 `조건1`이 거짓이면 `조건2`를 검사할까요? 어떤 코드가 어떤 순서로 실행될까요?

   ```text
   if (조건1):
       if (조건2):
           (코드1)
       else:
           (코드2)
   else:
       (코드3)
   (코드4)
   ```

2. 다음 코드에서 `item = "쿠키"`, `paid = 2000`으로 바꾸면 어떤 문장이 순서대로 출력될까요?

   ```python
   menu = {"커피": 4800, "쿠키": 2500}
   item = "커피"
   paid = 5000

   if item in menu:
       price = menu[item]

       if paid >= price:
           change = paid - price
           print(f"결제 완료. 거스름돈은 {change:,}원입니다.")
       else:
           shortage = price - paid
           print(f"{shortage:,}원이 부족합니다.")
   else:
       print(f"판매하지 않는 메뉴입니다. ({item})")

   print("주문 확인을 마쳤습니다.")
   ```

3. 다음 코드에서 `item`을 `"주스"`로 바꾸고, `price = menu[item]` 줄을 바깥쪽 `if` 바로 위로 옮겨 들여쓰기 없이 실행하면 어떤 일이 생길까요?

   ```python
   menu = {"커피": 4800, "쿠키": 2500}
   item = "커피"
   paid = 5000

   if item in menu:
       price = menu[item]

       if paid >= price:
           change = paid - price
           print(f"결제 완료. 거스름돈은 {change:,}원입니다.")
       else:
           shortage = price - paid
           print(f"{shortage:,}원이 부족합니다.")
   else:
       print(f"판매하지 않는 메뉴입니다. ({item})")

   print("주문 확인을 마쳤습니다.")
   ```

<details>
<summary>정답 확인</summary>

1. `조건2`는 검사하지 않습니다. 바깥쪽 `else`에 속한 `코드3`을 먼저 실행한 뒤 조건문 바깥의 `코드4`를 실행합니다.
2. 첫 번째 줄에 `500원이 부족합니다.`, 두 번째 줄에 `주문 확인을 마쳤습니다.`가 출력됩니다.
3. 메뉴가 등록되어 있는지 확인하기도 전에 `menu["주스"]`를 조회하므로, 존재하지 않는 키를 찾으려다 `KeyError` 오류가 발생합니다.
