# 5.5. Nested Conditions

카페에서 주문한 메뉴의 가격을 읽으려면 먼저 가격표에 등록된 메뉴인지 확인해야 합니다. 메뉴가 등록되어 있을 때만 가격을 조회할 수 있고, 그다음에 손님이 낸 돈이 충분한지 확인해야 합니다. 이처럼 어떤 조건을 통과한 뒤에만 다음 조건을 검사해야 할 때 조건문 안에 또 다른 조건문을 넣습니다.

## 5.5.1. 조건문 안에 조건문 넣기

`if` 블록 안에 또 다른 `if`문을 넣는 구조를 **중첩 조건문**(**Nested Conditional Statement**)이라고 합니다. 안쪽 `if`문은 바깥쪽 `if`문의 실행 블록에 속하므로, 바깥쪽 조건이 참(`True`)일 때만 안쪽 조건을 검사합니다.

```text
if (조건1):
    if (조건2):
        (코드1)
    else:
        (코드2)
else:
    (코드3)
(코드4)
```

> 만약 `조건1`이 참이라면 `조건2`를 검사합니다. 이때 `조건2`도 참이라면 `코드1`을, 거짓이라면 `코드2`를 실행합니다.  
> 반대로 `조건1`이 거짓이라면 안쪽 조건문 전체를 건너뛰고 바깥쪽 `else`의 `코드3`을 실행합니다.

`코드4`는 바깥쪽 조건문 블록 밖에 있으므로 어느 분기를 거쳤든 조건문이 끝난 뒤 항상 실행됩니다. 들여쓰기 깊이를 비교해 보면 어느 `else`가 어느 `if`와 짝을 이루는지 명확히 알 수 있습니다. 안쪽 `if`와 `else`는 공백 네 칸, 그 아래에서 실행할 코드는 공백 여덟 칸을 들여씁니다.

> 파이썬에서는 들여쓰기 칸 수가 곧 코드 블록의 소속을 결정합니다. 중첩 조건문을 작성할 때는 공백 네 칸(1단계)과 여덟 칸(2단계)의 들여쓰기 간격이 어긋나지 않도록 특히 주의해야 합니다.

## 5.5.2. 메뉴를 확인한 뒤 결제하기

바깥쪽 조건문에서는 주문한 메뉴가 메뉴판(`menu`)에 등록되어 있는지 먼저 확인합니다. 메뉴가 등록되어 있으면 `menu[item]`으로 가격을 읽어 오고, 이어서 안쪽 조건문에서 손님이 낸 돈과 가격을 비교해 결제를 진행합니다.

```python
menu = {"커피": 4800, "쿠키": 2500}
item = "커피"
paid = 5000

if item in menu:
    price = menu[item]

    if paid >= price:
        change = paid - price
        print(f"결제 완료. 거스름돈은 {change:,}원입니다.")
    else:
        shortage = price - paid
        print(f"{shortage:,}원이 부족합니다.")
else:
    print(f"판매하지 않는 메뉴입니다. ({item})")

print("주문 확인을 마쳤습니다.")
```

**실행 결과**

```text
결제 완료. 거스름돈은 200원입니다.
주문 확인을 마쳤습니다.
```

> 포맷 문자열 안의 `{change:,}`에서 `:,`는 숫자에 천 단위 구분 쉼표(`,`)를 자동으로 넣어 주는 서식 지정자입니다. 예를 들어 `1200`은 `1,200`으로 깔끔하게 출력됩니다.

변수 `item`과 `paid`의 값을 아래 표처럼 바꾸어 보며 어느 분기가 실행되는지 직접 확인해 보세요.

메뉴판에 없는 `"주스"`를 주문하면 바깥쪽 조건(`item in menu`)이 거짓이 되어 곧바로 바깥쪽 `else` 분기로 이동합니다. 이때 가격을 읽는 `price = menu[item]` 줄도 실행하지 않고 건너뛰므로, 딕셔너리에 없는 키를 조회할 때 발생하는 `KeyError` 오류를 안전하게 피할 수 있습니다.

## 5.5.3. 조건을 묶을 때와 중첩할 때

5.4절에서 배운 논리 연산자 `and`를 사용하면 두 조건을 한 줄로 묶어서 확인할 수도 있습니다. 다음 코드처럼 작성하면 왼쪽의 `item in menu`가 참일 때만 오른쪽의 가격 비교(`paid >= menu[item]`)를 이어서 검사합니다.

```python
menu = {"커피": 4800, "쿠키": 2500}
item = "주스"
paid = 5000

if item in menu and paid >= menu[item]:
    print("결제할 수 있습니다.")
else:
    print("결제할 수 없습니다.")
```

**실행 결과**

```text
결제할 수 없습니다.
```

> `and` 연산자는 왼쪽 조건이 거짓이면 오른쪽 조건은 아예 평가하지 않고 즉시 전체 결과를 `False`로 확정합니다. 이러한 동작 방식을 **단락 평가**(**Short-circuit Evaluation**)라고 합니다. 덕분에 `item`이 `"주스"`일 때도 `menu["주스"]`를 실행하지 않아 `KeyError`가 발생하지 않습니다.

단순히 결제 가능 여부만 알려 주려면 `and`로 묶은 형태만으로도 충분합니다. 하지만 메뉴가 없을 때와 돈이 부족할 때 **상황별로 서로 다른 안내 문구**를 보여 주려면, 5.5.2절처럼 중첩 조건문을 사용해 각각의 경우를 세분화하여 처리해야 합니다.

| 구분 | 조건을 `and`로 묶기 | 중첩 조건문(`if` 안의 `if`) 사용하기 |
| :---: | :---: | :---: |
| **적합한 상황** | 모든 조건을 만족하는지만 간단히 확인할 때 | 조건이 거짓인 이유에 따라 각각 다르게 안내할 때 |
| **코드 길이** | 한 줄로 짧고 간결함 | 분기가 나뉘어 상대적으로 길어짐 |
| **예제 동작** | `"결제할 수 없습니다."` 한 가지로 통일해 안내 | 메뉴 없음과 잔액 부족을 구분해 맞춤 안내 |

> 중첩 조건문은 상황을 세밀하게 나누어 처리할 때 유용하지만, 조건문을 3단계 이상 너무 깊게 중첩하면 들여쓰기가 복잡해져 코드를 읽고 수정하기 어려워집니다. 가능하면 2단계 이내로 간결하게 유지하는 것이 좋습니다.

## 확인 문제

2. 5.5.2절의 예제에서 `item = "쿠키"`, `paid = 2000`으로 설정하면 어떤 문장이 순서대로 출력될까요?
3. 5.5.2절의 `price = menu[item]` 코드를 바깥쪽 `if`문보다 위쪽으로 옮기면, `"주스"`를 주문했을 때 어떤 일이 생길까요?
